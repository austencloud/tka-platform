Sequence Viewer: Animation Audit

Current state — what's working and what's fighting itself

The Timing Problem

Right now the viewer uses 5 different durations and 4 different easing curves across components that animate together. When the user clicks "focus on animation pane," here's what fires simultaneously:

Grid collapse
300ms ease-out
Pane opacity
300ms different curve
Export panel fade
200ms cubicOut
Close button
250ms spring bounce
Border color
250ms ease

Five animations, five different timings, four different easing curves. They finish at different times, which is why things feel unsettled — the eye sees multiple endpoints instead of one cohesive motion.

The Four Easing Curves

Drawer
cubic-bezier(0.16, 1, 0.3, 1)
Fast start, soft landing
Split Pane
cubic-bezier(0.25, 0.46, 0.45, 0.94)
Gradual ease-out
Close Button
cubic-bezier(0.34, 1.56, 0.64, 1)
Spring overshoot
View Transition
cubic-bezier(0.4, 0, 0.2, 1)
Material standard

Each curve was chosen in isolation. Together they create subtle visual dissonance — like an orchestra where each musician is playing at their own tempo.

The Layout Shift Sources

Three places where the layout visibly jumps instead of flowing:

1
Export panel swap
Video and image panels had different heights. When switching, the old panel's slide-out competed with the new panel's slide-in. (Fixed today — switched to fade + single container)
2
Footer doesn't hide during export
The Save/Construct/Video/Image toolbar + playback controls stay visible during export mode. On mobile that's ~100px of screen eaten by controls you can't use while exporting.
3
Split pane entry has dead time
The split pane fades in with a 50ms delay + 250ms duration after the drawer's 350ms open. That's 650ms before content is fully visible — the user sees a dark void inside the drawer for a beat.
