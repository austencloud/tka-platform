Wall Mode vs Split-Plane Mode

Top-down view (looking down at the performer from above)

Current: Wall Mode

PROBLEM

Both hands reach to positions on a single plane in front of the body. Cross-body positions force the arms through the torso and head.

Proposed: Split-Plane Mode

SOLUTION

Avatar turns 90 degrees. Each hand gets its own plane extending outward from the body. Arms open naturally to each side. No clipping.

Front View (what the audience sees)

Same positions, different avatar orientation

Wall Mode: Front View

Split-Plane Mode: Front View

What already exists in the codebase

  • Plane enum already has WALL, WHEEL, FLOOR values
  • planeAngleToWorldPosition() already maps compass points to 3D coords per plane
  • facingAngle prop on Avatar3D already rotates the skeleton
  • PropState3D.plane already carries which plane each hand is on
  • ElbowPoleComputer already uses plane info for elbow direction

What needs to be built

  • Detection logic: when does a beat need split-plane mode? (both hands crossing to opposite sides)
  • Avatar facing rotation: turn 90 degrees when entering split-plane mode
  • Per-hand plane assignment: left hand = left wheel, right hand = right wheel
  • Smooth transition between wall mode and split-plane mode during a sequence
  • Decide: auto-detect vs explicit mode flag per beat
