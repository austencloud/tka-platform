# Queue Skill & Spec Restructure

**Date:** 2026-04-26
**Status:** Shipped

## Problem

242 specs and 187 plans in flat directories with no status metadata. Cold-start agents spent 10+ minutes triaging before picking work. Partial/forgotten/superseded categories were vague and overlapping.

## Solution

### Directory Restructure

```
docs/superpowers/
  QUEUE.md              ← snapshot, regenerated by /queue
  specs/
    shipped/   162      ← completed
    active/      5      ← in-flight with resume points
    backlog/    54      ← triaged and scored
    archived/   21      ← superseded, rejected, or shelved
  plans/
    shipped/   137
    active/      4
    backlog/    46
```

### YAML Frontmatter on Every Active/Backlog Spec

```yaml
---
status: backlog
value: 4
effort: M
score: 12
remaining: "One-line description of what's left"
blocked_by: ""
last_triaged: 2026-04-26
---
```

### /queue Skill

Reads frontmatter from all active + backlog specs, computes scores (value x effort multiplier), outputs a live ranked table grouped by tier. Flags stale specs (>30 days since last triage) and blocked specs.

## Scoring

| Effort | Multiplier | Rationale |
|--------|-----------|-----------|
| XS | 5 | Quick wins 5x more attractive than XL at same value |
| S | 4 | |
| M | 3 | |
| L | 2 | |
| XL | 1 | |

## Triage Methodology

Each spec was assessed by:
1. Reading spec scope (first 30 lines)
2. Grepping codebase for key deliverables
3. Checking git log for related commits
4. Scoring value (1-5) based on user impact and strategic importance
5. Estimating remaining effort after accounting for what already shipped

Three parallel agents triaged 46 partial specs. A fourth cross-linked all specs against all plans to identify orphans (32 orphan plans, 75 orphan specs).
