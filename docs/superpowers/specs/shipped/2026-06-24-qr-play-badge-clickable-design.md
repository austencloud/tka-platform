# Clickable QR Play Badge → 2D Animation

**Date:** 2026-06-24
**Status:** Design — awaiting approval
**Author:** Austen + Claude

## Problem

In the sequence viewer's **Card** mode (the download-card section), the QR code
shows a green play-triangle badge baked into its center. It reads as a "scan to
play" affordance but has no on-screen click behavior. The natural impulse is to
click that play button and land in the 2D animation viewer, the same way
switching tabs would. Today nothing happens.

## Goal

Clicking the play badge in the Card-mode QR switches the viewer to **2D
Animation** mode and starts playback, with a hover/focus affordance signaling the
badge is interactive. Scope is the interactive viewer only.

## Background — current rendering

- The play triangle is part of the QR **image**, not a separate element. The QR
  is generated by `qr-code-styling` with `image: playIconDataUrl(...)`,
  `imageOptions.imageSize: 0.25` and `hideBackgroundDots: true`
  (`src/lib/shared/qr/services/qr-code-generator.ts`). So the badge occupies the
  centered **25%** of the QR, and the QR modules directly behind it are cleared —
  there is no scannable data under the badge.
- The card renders the QR as a plain `<img class="qr-code-image" src={qrDataUrl}>`
  in **four** sites inside
  `src/lib/shared/sequence-viewer/components/CardGridLayout.svelte` — duration
  layout (scroll + standard) and uniform grid (scroll + standard), at lines
  ~224, ~306, ~462, ~574. All four need the overlay treatment.
- Viewer modes live in
  `src/lib/shared/sequence-viewer/state/viewer-state.svelte.ts`. **2D = the
  `animation` mode.** `SequenceViewerDrawerHost.svelte` already routes mode
  switches through `selectViewerMode(ctx, mode)` →
  `ctx.viewerState.enterExport('animation-export', 'animation')` for 2D.
- The QR only renders for **signed-in** users; guests get no QR
  (`QRMandalaOverlay` / `ChoreoCard` clear the slot for guests). The play badge
  therefore only exists where a QR exists — no guest fallback in scope.

## Design

### 1. Clickable overlay (geometry)

Wrap the QR `<img>` in a `position: relative` container and overlay a
transparent, centered `<button>` covering the play badge:

- Centered 25% box → `inset: 37.5%` on the wrapper.
- Floor the rendered hit area at the **44px** touch-target minimum
  (`min-width`/`min-height`), so the target stays tappable when the QR is small
  (mobile split pane). The cleared center has no scannable modules, so a hit area
  up to ~25–28% never overlaps QR data.
- The `<img>` underneath is unchanged — still a valid, scannable QR.

The button is purely a hit area + affordance; it draws no second play glyph (the
badge underneath is the icon).

### 2. Behavior (switch + auto-play)

On click the handler (defined in `SequenceViewerDrawerHost`, closing over the
orchestrator `ctx`):

```ts
function playFromQr(ctx: OrchestratorContext) {
  selectViewerMode(ctx, 'animation');           // existing 2D-animation switch
  if (!ctx.isPlayingLocal) ctx.handlePlaybackToggle(); // start, never pause a running anim
}
```

- Reuses the **existing** mode-switch path (`selectViewerMode`) — identical to
  the rail / bottom-bar route, so no new mode logic.
- `handlePlaybackToggle` is a toggle; the `isPlayingLocal` guard makes this an
  idempotent **start** (clicking while already playing won't stop it).
- If verification surfaces a canvas-ready race (mode just mounted the 2D pane),
  defer the play call one tick (microtask / short `setTimeout`, as
  `selectSplitMode` already does with its `rerenderTrigger` timeout). Confirm the
  exact timing during verification rather than guessing.

### 3. Hover / focus affordance + a11y

- `<button type="button" aria-label="Play in 2D" title="Play in 2D">`.
- `cursor: pointer`.
- On `:hover` / `:focus-visible`: a soft circular ring + subtle scale "pop" via a
  pseudo-element centered on the badge — enough to say "this does something."
- `:focus-visible` outline for keyboard users.
- Wrapped in `@media (prefers-reduced-motion: reduce)` to drop the scale/transition.

### 4. Plumbing (optional callback — mirrors `onStepClick`)

Add an optional `onQrPlayClick?: () => void` prop threaded the same way
`onStepClick` already is:

| File | Change |
|---|---|
| `CardGridLayout.svelte` | Add `onQrPlayClick?` prop. At each QR render site, when `onQrPlayClick` is set, render the wrapper + overlay button; otherwise render today's bare `<img>`. Add overlay CSS. |
| `ChoreoCard.svelte` | Add `onQrPlayClick?` prop; pass through to `CardGridLayout`. |
| `ViewerSplitPane.svelte` | Add `onQrPlayClick?` prop; pass to **both** Card `ChoreoCard` instances (left pane ~532, right pane ~660). |
| `SequenceViewerDrawerHost.svelte` | Define `playFromQr(ctx)`; pass `onQrPlayClick={() => playFromQr(ctx)}` to `ViewerSplitPane`. |

### 5. Gating

The overlay renders **only** when `onQrPlayClick` is provided. The only caller
that provides it is `SequenceViewerDrawerHost` (the interactive viewer).
Therefore unchanged, byte-for-byte, in every other consumer of `ChoreoCard` /
`CardGridLayout`:

- the image-export / download render pipeline,
- printed cards,
- landing-page and browse-gallery previews,
- `SequenceViewer.svelte`'s own `ChoreoCard` usage.

In those contexts the badge stays a pure scan visual.

## Non-goals

- No guest fallback badge (guests have no QR).
- No whole-QR click target (badge only, per decision).
- No change to the QR image, encoded URL, or scan behavior.
- No new top-level "Play in 2D" chrome on the card.

## Verification

- Interactive viewer, Card mode, signed in: hover the badge shows the affordance;
  click switches to 2D Animation and playback starts. Evidence: runtime / DevTools
  (with permission) or screenshot.
- Already-playing guard: clicking while the animation runs does not stop it.
- Regression: export/print/landing/browse and `SequenceViewer.svelte` card render
  show no overlay and unchanged markup (the `<img>` path).
- QR still scans (badge hit area sits over cleared center).
- `npm run check` clean.
