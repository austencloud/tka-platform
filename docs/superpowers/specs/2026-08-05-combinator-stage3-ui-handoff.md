## Done — verified

### 1. The group behind the 13 families — `641c375731`, `8b8baab6e2`

`scripts/combinator-research/letter-group.mjs` composes every structural
transform as a permutation of all 1152 pictographs. Working on pictographs
rather than letters is the trick: on letters the maps are many-valued (A rotated
90° is S, and so is A rotated 270°), so no group acts on letters at all. Letters
are the quotient.

Reproduce: `node scripts/combinator-research/letter-group.mjs` (seconds).

| Generated by | Order | Letter classes |
|---|---|---|
| gap step alone (one hand, 90°) | 4 | **13** — the families, re-derived |
| gap involution × twin involution | 4 (Klein four) | 18 |
| gap step × twin | **8** | **9** |
| every closed transform | 256 | 7 |

- **The two involutions COMMUTE.** Klein four-group. Nothing deeper is hiding at
  the level the previous handoff asked about.
- **`letter = (character, gap)` is a measured bijection**: the gap step has 288
  orbits, all free of size 4, each hitting each of the four even gaps **exactly
  once — 288 of 288, 100%**. So 288 characters × 4 gaps = 1152 pictographs, no
  exceptions, no leftovers.
- **Family-size law**: size 3 exactly when the two gamma slots share one letter
  name, size 4 when they carry different names. Nothing else varies.
- **Skew is 0% closed** — rotating one hand 45° lands off the shipped map for
  **1152 of 1152**, not merely "no rows start from a skewed position."
- Colour swap, reflection, and both-hands-45° (diamond↔box) are **100%
  letter-preserving**.

Cross-checked against the domain server the same day: `compare_letters("S","A")`
returns 16 variations for S against 8 for A with the *only* difference being
`gamma→gamma` vs `alpha→alpha`; `compare_letters("M","P")` returns 8 each and
"no major differences". That is the family-size law from a separate code path.

### 2. The fingerprint law — `641c375731`, `8b8baab6e2`

`node scripts/combinator-research/pair-classes.mjs` (~15 min) states a model,
derives each prediction from structure, measures, and scores itself.

> **Every cross-world card pair is 512 words. It halves to 256 exactly when the
> two cards are gap-involution partners — the same motion character at opposite
> gaps (A↔G, B↔H, C↔I). Separation into gamma never halves.**

**18 pairs, 18 correct.** The first model (a base per separation, halved
whenever the cards share a family) was **refuted**: it predicted 1024 for A+U,
A+T and B+S, which all measured 512. The refutation is recorded in the script so
nobody re-derives the wrong version.

### 3. The dash prop-reversal bug — `25200da2c1`

`mcp-server-pkg/src/core/constraints/analysis/transition-analyzer.ts`
`getEffectivePropRotation` guarded on `motionType === "static"` and cast
everything else to `"cw" | "ccw"`. A dash carries `noRotation`, so every dash
scored as a prop reversal.

Evidence — bundled the analyzer pre- and post-fix and ran it over the real A and
Ψ pictographs from the canonical dataframe:

| | valid transitions | no prop reversal | `canAvoidPropReversal` |
|---|---|---|---|
| before | 16 | **0** | false |
| after | 16 | **16** | true |

All 16 flip. The fix guards on the VALUE, not the motion type, matching the
canonical `channelFlips` in `packages/sequence-engine/src/analysis/deriveReversals.ts`.
**The previous handoff's diagnosis ("the guard is present in five other
implementations") was wrong** — the siblings guard `static` for *generation*
constraints, a different concern.

⚠️ **NOT LIVE.** Needs an `mcp-server-pkg` build + MCP server restart. Confirmed
still serving the old `dist` at session end: `get_sequence_data("AJGΦ")` reports
"2 reversals in 4 beats" for continuity while the feasibility warning claims "3
unavoidable".

## Gotchas

1. **`validate_loop_options` defaults `period` to `"halved"`.** Re-confirmed
   live: `alpha3→alpha5` returns only `rewound` with the period omitted, versus
   `rotated` + `rotated_inverted` + `rotated_swapped` at `quartered`. Omit it
   and the entire 16-count bucket vanishes.
2. **`rewound` is admissible at EVERY position pair** (checked at two).
   Counting it makes "discard anything admitting no LOOP" vacuous. Stage 3
   excludes it by default behind `includeRewound`.
3. **Never derive VTG direction from the two `rotationDirection` fields.** For a
   hybrid the props counter-rotate while the hands travel together, so
   prop-direction agreement is the INVERSE of hand-direction agreement —
   deriving it that way labels C/I/U/V "opposite" and F/L/O/R "same", which is
   backwards. Use the dataframe's own `direction` column. **This session made
   that exact error and briefly published it** before catching it.
4. **The walk cap is a function of roster size.** `CANDIDATE_WORD_MAX_RESULTS`
   in `get-sequence-combinator.ts` is 16,384 and was bisected, not chosen. Any
   roster addition can silently flip `searchComplete` to false. The redesign
   deletes the cap outright; treat the number as a stopgap with an expiry date.
5. **`isLOOPValidForPositionPair` is marked `@deprecated`** in favour of
   `isLOOPValidForSpec`. Stage 3 uses it as instructed and notes it.
6. **The app-side `LOOPType` is NOT value-identical to the engine's** — the app
   copy in `foundation/domain/models/generation/circular-models` spells rewound
   `strict_rewound`. Results carry the ENGINE's enum; map, never cast.
7. **A word does not identify a discovery.** Keying UI rows by word+closure
   throws `each_key_duplicate` on the real A+G answer (`AJGF:plain` twice).
   Two distinct realizations share a word, and phases are separate rows.
8. **The lab shell clips.** `LabModule .lab-module` is `height:100%; overflow:
   hidden`, so a tab that just grows is unreachable below the fold with no
   scrollbar. A tab owns its own scroller, and `min-height: 0` is load-bearing —
   without it a flex child will not shrink below its content and `overflow-y`
   never engages.
9. **`svelte-check` passing means nothing about whether the page works.** It
   reported 0 errors on a version that rendered a blank results area. Three
   defects this session were browser-only: the duplicate key, the wrong
   counting altitude, and ~75% dead space per row.
10. **MCP sequence RENDERING is still down** (`canvas` package missing).
    `generate_pictograph` and `get_sequence_data` work; `generate_sequence`
    fails. Use `get_sequence_data` for theory tests.
11. **`detect_loop_pattern` is non-deterministic.** Never validate combinator
    output with it.
12. **Parallel sessions make browser verification flaky.** Vite full-reloads
    reset component state between tool calls. Batch click-and-measure into ONE
    `evaluate_script`, and expect `element.click()` to sometimes not reach the
    Svelte handler after a remount.
