# Level 1 Guide — Proofing + Reprint Loop

**Date:** 2026-06-21
**Status:** Approved (design)
**Author:** Austen Cloud (via Claude)

## Problem

The Level 1 guide shipped as a printable v1 (`/guide/level-1/print` → headless
Chrome → `static/guides/level-1.pdf`). Two gaps remain in the day-to-day loop:

1. **No repeatable reprint.** The v1 PDF was generated by a hand-typed headless
   Chrome command. Editing a section's prose and getting a fresh PDF means
   remembering that command. The user wants a one-command reprint.
2. **No page-by-page proofing.** There's no way to lay the old v0.5 PDF next to
   the current output and confirm v1 didn't drop or mangle content. The existing
   parity harnesses (`CardParityViewer`, `ParityHarness`) are automated pixel-diff
   gates tied to the `ParityRun` engine and assume equal page counts — they don't
   fit (old v0.5 and current have different page counts; this is human proofing,
   not a PASS/FAIL gate).

## Decision: keep Svelte authoring, do NOT move to markdown

The guide content is prose interleaved with data-driven Svelte components
(`<GuidePictographGrid rows={…} columnHeaders={…}/>`, `<LessonGridDisplay/>`,
motion demos, codex tables). Prose is ~30-40%; the rest is component calls with
structured props (pictograph-ID arrays from a shared context).

- **Plain markdown:** dead end — can't express the pictograph components.
- **MDX / mdsvex:** technically possible, but adds a preprocessor + config + a
  38-file migration, while only prettifying the 30% that is already readable
  plain English in `<p>` tags. The hard 60% (pictograph data wiring in `<script>`
  blocks) is unchanged. Also risks the working print pipeline (print-mode context,
  eager render, page-break CSS all assume the component tree).
- **Chosen:** keep `.svelte` sections as-is. The real "edits easy" win is the
  reprint script, not a new authoring format.

## Deliverable 1 — Reprint script

**File:** `scripts/build-guide-pdf.mjs` (ESM, matches existing `scripts/*.mjs`).
**npm script:** `"guide:pdf": "node scripts/build-guide-pdf.mjs"` in `package.json`.

Behavior:
1. Resolve Chrome at `C:\Program Files\Google\Chrome\Application\chrome.exe`
   (overridable via `CHROME_PATH` env).
2. Target URL defaults to `http://localhost:5173/guide/level-1/print`
   (overridable via `--url`). Probe it first (HTTP GET). If unreachable, exit
   non-zero with the explicit command to start a dev/preview server. Never run
   `npm run dev` (hooks block it).
3. Invoke headless Chrome:
   `chrome --headless=new --disable-gpu --no-pdf-header-footer
   --virtual-time-budget=30000 --print-to-pdf=<temp> <url>`.
   The 30s virtual-time budget lets the print-mode context render every
   pictograph eagerly before capture.
4. Validate the temp PDF with **pdf-lib** (already installed): load it, assert
   `getPageCount() > 50` and file size > 1MB. Fail loud on a blank/short render
   rather than overwriting a good PDF with a bad one.
5. Back up the existing `static/guides/level-1.pdf` to
   `<os.tmpdir()>/level-1-prev-<n>.pdf`, then move the temp into place.
6. Print a summary (page count, size, output path as a clickable link).

**Known issue (flagged, out of scope):** `static/guides/level-1.pdf` is a ~15.7MB
binary committed to git so it serves at the landing-page download link.
Regenerating churns 15MB per commit. Not fixed here; noted for a future decision
(e.g. stop committing it, or move it to object storage).

## Deliverable 2 — Proofing viewer

**Route:** `src/routes/test/guide-proof/+page.svelte` + `+page.ts`
(`export const prerender = false; export const ssr = false;` — pdfjs is
browser-only).

**New dependency:** `pdfjs-dist` as a **devDependency** (`pnpm add -D
pdfjs-dist`). It is the standard PDF→canvas renderer; grep found zero existing
`pdfjs` usage and `pdf-lib` cannot rasterize pages. Worker wired via Vite's
`?url` import (`pdfjs-dist/build/pdf.worker.min.mjs?url` →
`GlobalWorkerOptions.workerSrc`); exact API confirmed against current pdfjs-dist
docs at implementation time.

**Reuse note:** `CardParityViewer`/`ParityHarness` were read and rejected — they
are coupled to the `ParityRun` pixel-diff pipeline and a PASS/FAIL verdict, which
this human-proofing tool does not have. The new viewer follows the same dark
render-lab visual conventions (sticky bar, dark bg, framed canvases) without the
engine coupling.

**Layout & behavior:**
- Two columns: **left = old v0.5**, **right = current**, each rendered page-by-page
  to `<canvas>` at a readable width.
- **Synced scroll** between columns, with a **page-offset nudge** (±) so the user
  can align mismatched page counts by hand.
- **Overlay mode toggle:** superimpose a single page pair with an opacity slider
  to check one page's alignment precisely.
- **Page jump** input. No thumbnail rail, no automated diff (YAGNI; page counts
  differ so pixel-diff would mislead).
- Render lazily per page (render on scroll into view) to avoid rasterizing all
  ~63+ pages up front.

**Old-PDF asset handling (avoids git/prod bloat):**
- Copy `/tmp/level-1-v05-backup.pdf` → `static/guides/_proof/level-1-v05.pdf`
  during implementation.
- Add `static/guides/_proof/` to `.gitignore`. The ~18MB reference stays local;
  never committed, never shipped to prod.
- Viewer loads left from `/guides/_proof/level-1-v05.pdf`, right from the live
  `/guides/level-1.pdf`. If the left file 404s, the viewer shows a one-line hint
  naming the source path to copy from.

**Discoverability:** add a third card to the `/test/parity` hub linking
`/test/guide-proof` (labeled as a proofing tool, not a parity gate).

## Out of scope / YAGNI
- Markdown/mdsvex migration (rejected above).
- Automated pixel-diff verdict for the guide.
- Thumbnail navigation rail.
- Multi-level (L2/L3) proofing — single-level only; generalize later if needed.
- Fixing the committed-binary bloat.

## Verification
- Run `npm run guide:pdf` against the running dev server; confirm it writes a
  valid 60+ page PDF and rejects a blank render (temporarily point `--url` at a
  404 to prove the guard).
- Load `/test/guide-proof`; confirm both PDFs render, synced scroll + offset
  nudge work, and overlay opacity blends a page pair.
- `npm run check` clean for all new/edited files.
