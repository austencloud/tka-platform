# Fuse Tab — Dual-Sequence Composition

**Goal:** A new tab in the Create module where users compose sequences by selecting two sequences side by side and fusing them into one. Live animation previews play while browsing. The fuse action triggers a reassembly animation (reverse of the existing disassemble transition), followed by a celebration effect.

**Feedback:** ms2hMGeJo6fOeSb3jelo

**Tech Stack:** Svelte 5, ITI DI, AnimatorCanvas, Web Animations API, SequencePickerModal

## User Flow — Step by Step

### Phase 1: Browse

User enters the Fuse tab and sees two side-by-side browser panels. Each panel is a scrollable grid of choreo card thumbnails (max 2 columns). Both browsers use the same `SequencePickerModal` filtering infrastructure (search, level filter, length filter, favorites) but rendered inline rather than in a modal.

### Phase 2: Pick Left

User taps a sequence in the left browser. The browser panel is replaced by a live AnimatorCanvas showing that sequence looping. The right browser stays visible for browsing.

### Phase 3: Pick Right

While the left animation loops, the user scrolls the right browser and picks a second sequence. The right browser is replaced by a live AnimatorCanvas. Both canvases animate in sync (same BPM, same playback position).

### Phase 4: Fuse

A "Fuse" button appears (centered between the two panels, or below on mobile). Tapping it triggers:

1. **Assembly animation** — Both canvases slide together and merge into a single canvas at center. This uses the same FLIP technique and easing curves as `DisassembleTransition.svelte`, but the geometry is fundamentally different: disassemble operates on a 3-element layout (one hero + two sub-canvases) within a single component, while fuse has two independent panels in a CSS grid converging to center. The directly reusable piece is `calcFlipTransform()` (~10 lines of center-point math) and the easing curve values (`cubic-bezier(0.16, 1, 0.3, 1)`). The rest of the animation logic is new.
2. **Celebration effect** — Particle burst / fireworks on completion. 800ms duration, purely decorative.
3. **Result preview** — The fused sequence plays in a single centered AnimatorCanvas.

### Phase 5: Post-Fuse Actions

Three buttons below the result canvas:

| Action | Behavior |
|--------|----------|
| **Save** | Opens `SaveToLibraryPanel` with the fused sequence |
| **Build Another** | Resets to Phase 1 (both browsers) |
| **See Related** | Navigates to Browse module filtered by the fused sequence's starting position |

## Animation Synchronization

The left and right canvases each own independent `AnimationPlaybackController` and `AnimationPanelState` instances. Synchronization is handled by the Fuse tab's state factory:

### How It Works

1. When the first sequence is selected, create `leftPlaybackController` and start playback immediately.
2. When the second sequence is selected, create `rightPlaybackController`. Before starting playback, read `leftAnimationState.currentStep` and call `rightPlaybackController.seekToStep(currentStep)` to sync. Then start both. **Note:** `seekToStep(beat)` exists on `IAnimationPlaybackController` — verify during implementation that it handles mid-sequence seeking correctly (not just reset-to-beat-1 usage). If it doesn't support arbitrary step seeking, a new method may be needed.
3. A shared BPM drives both controllers via `setSpeed(bpm / 60)`. A single `TempoControl` widget controls both.

### Length Mismatch Handling

When sequences have different beat counts:

- **Default (independent loop mode):** Both loop independently at their own length. Because they share BPM, each beat stays rhythmically aligned, but the shorter sequence will reset to beat 1 while the longer one is still mid-sequence. This is expected and visually fine — the user sees two independent loops running at the same tempo. No re-sync is needed on loop boundaries; each panel's controller manages its own loop independently.
- **Power user toggle (LCM mode):** The shorter sequence loops multiple times to fill the LCM of both lengths. Example: 4-beat + 6-beat = 12-beat fused sequence. The 4-beat plays 3 times, the 6-beat plays 2 times.

The toggle is a small chip below the Fuse button: "Match lengths" (default on). When off, the LCM logic determines the fused sequence length.

### LCM Calculation

```ts
function gcd(a: number, b: number): number {
  return b === 0 ? a : gcd(b, a % b);
}

function lcm(a: number, b: number): number {
  return (a * b) / gcd(a, b);
}
```

This maps directly to traditional CAPs composition: combining two hand paths of different lengths produces a sequence whose length is the LCM of the individual lengths.

## Assembly Animation (Reverse Disassemble)

Uses the same FLIP technique and easing curves as `DisassembleTransition.svelte` (`src/lib/shared/animation-engine/components/DisassembleTransition.svelte`), but the geometry is fundamentally different.

### How Disassemble Differs

The disassemble animation operates on a 3-element layout (one hero + two sub-canvases) within a single component. The fuse animation has two independent panels in a CSS grid converging to center. The only directly reusable pieces are `calcFlipTransform()` (~10 lines of center-point math) and the easing curve values. The animation orchestration logic is new.

### Fuse Assembly Flow (New)

Two independent CSS grid panels animate toward a shared center point:

1. Measure both panel rects and compute a target center rect.
2. Animate both panels toward the center: `translate(tx, ty) scale(sx, sy)` over 600ms.
3. During the last 150ms, fade both panels' opacity to 0.
4. On animation finish, mount the single fused AnimatorCanvas at center.
5. Fire the celebration effect.

The animation math lives in a new `FuseAssemblyAnimator` service (not a component — pure DOM measurement + Web Animations API calls).

### Celebration Effect

Canvas-based particle system. Brief burst of orange/amber particles (matching the Fuse tab's color theme) radiating from the center point where the canvases merged. 800ms duration, 40-60 particles, physics: initial velocity + gravity + fade.

Implementation: a `<canvas>` overlay positioned absolutely over the result area, removed from DOM after the animation completes. No external library needed — a simple requestAnimationFrame loop with particle state arrays.

### State Factory: `fuse-state.svelte.ts`

```ts
export type FusePhase = "browse" | "left-selected" | "both-selected" | "fusing" | "result";

export function createFuseState(deps: FuseDeps) {
  let phase = $state<FusePhase>("browse");
  let leftSequence = $state<SequenceData | null>(null);
  let rightSequence = $state<SequenceData | null>(null);
  let fusedSequence = $state<SequenceData | null>(null);
  let matchLengths = $state(true);

  // Playback controllers (created on selection)
  let leftController = $state<IAnimationPlaybackController | null>(null);
  let rightController = $state<IAnimationPlaybackController | null>(null);
  let leftAnimState = $state<AnimationPanelState | null>(null);
  let rightAnimState = $state<AnimationPanelState | null>(null);

  const canFuse = $derived(
    phase === "both-selected" &&
    leftSequence !== null &&
    rightSequence !== null
  );

  function selectLeft(seq: SequenceData) { ... }
  function selectRight(seq: SequenceData) { ... }
  function startFuse() { ... }
  function reset() { ... }
  function setBpm(newBpm: number) { ... }
  function setMatchLengths(match: boolean) { ... }

  return {
    get phase() { return phase; },
    get leftSequence() { return leftSequence; },
    get rightSequence() { return rightSequence; },
    get fusedSequence() { return fusedSequence; },
    get matchLengths() { return matchLengths; },
    get bpm() { return bpm; },
    get canFuse() { return canFuse; },
    get leftAnimState() { return leftAnimState; },
    get rightAnimState() { return rightAnimState; },

    setBpm,
    setMatchLengths,

}
```

## Keyboard and Accessibility

- **Space:** Toggle playback on the focused panel (or both if result view)
- **Escape:** If in result view, return to browse. If a panel has a sequence, deselect it.
- **Tab navigation:** Left browser -> Right browser -> Fuse button -> Post-fuse actions
- **Reduced motion:** Assembly animation skips to instant cut. Celebration effect disabled.
- **ARIA:** `role="region"` on each panel with `aria-label="Left sequence"` / `"Right sequence"`. Fuse button gets `aria-disabled` when `canFuse` is false.

---

## Persistence

Minimal. Store only `bpm` and `matchLengths` in localStorage under key `fuse-tab-state`. Selected sequences are not persisted — the tab always starts fresh in browse mode. This avoids stale references to sequences that may have been deleted.

## Integration with Create Module

The Fuse tab does NOT participate in the Create module's existing sequence state (`CreateModuleState`, `constructTabState`, `panelState`). It owns its own state factory and context, similar to how `DisassembleLab` operates independently.

However, the post-fuse "Save" action feeds into the shared `SaveToLibraryPanel`, and "See Related" navigates via `navigationState`.

The tab component (`FuseTab.svelte`) is loaded by `CreationToolPanelSlot` (`src/lib/features/create/shared/components/CreationToolPanelSlot.svelte`). That component uses hardcoded `{#if}`/`{:else if}` branches with direct imports — not dynamic lazy loading. Add an `{:else if activeToolPanel === "fuse"}` branch after the existing `assemble` branch, importing `FuseTab.svelte` directly at the top of the script. This matches how Construct, Assemble, and Generate are wired today. Since FuseTab owns its own state and doesn't participate in `CreateModuleState`, the branch body is simple — just `<FuseTab />`.
