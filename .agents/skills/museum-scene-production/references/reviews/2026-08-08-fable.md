## What is genuinely strong (keep unchanged)

1. **The authority/ownership table.** One owner per kind of truth, with
   `scene-gates.json` explicitly demoted to an evidence index. This directly
   targets the real historical failure (duplicated coordinates and prose
   drifting from the plan contract). Earth's contract uses it correctly.
2. **The literal / metaphor / invention claim taxonomy.** This is the best idea
   in the package. It cleanly separates MCP-provable domain facts from authored
   spectacle, and the validator enforces evidence on literal claims. Nothing
   else in the repo does this.
3. **The validator itself.** Real digest checking, gate-ordering enforcement,
   premature-work rejection, approval-record structure, exemption provenance,
   and a self-test. It caught nothing on Earth that human review missed — but it
   costs seconds and makes silent gate-skipping impossible.
4. **Failure evidence preserved, not deleted.** Earth's `revisionHistory` keeps
   both rejected Gate 2 packages and the invalidated Gate 1 approval with their
   digests. This is exactly the right instinct.
5. **The comprehension check** ("describe the route back to me before I record
   approval"). Earth's history proves the need: Gate 1 was approved with "Love
   it. Gate passed." and then invalidated by a free walk. Approval-by-enthusiasm
   is the documented slop path and the check targets it precisely.

## Critical findings (priority order)

### F1. The Gate 1 sightline contract still permits the exact failure that invalidated Earth's Gate 1

Earth's original Gate 1 proved clear rays **from fixed stops** and passed; free
walking then hid H and I under the route lip. The Gate 1.1 amendment invented
the fix — seven-sample **moving viewing windows aimed at the performer floor,
not the avatar centre** — but `gate-contracts.md` was never updated. Its
`sightlines` check still says nothing about continuous sampling or foot-line
targeting, so the next scene can pass Gate 1 with fixed-stop rays and re-learn
this at graybox cost.

**Fix:** In Gate 1's required checks, define `sightlines` as continuous
route-sampled visibility windows per performer/hero, with rays aimed at the
lowest point that must remain visible (feet/floor), plus a worst-case clearance
number. This is the single highest-value change in the whole revision.

### F2. `motion-proof` accepts a still image, contradicting the skill's own rule

`visual-bridge.md` says "Capture continuous motion as a loop. A still frame
cannot prove timing." Earth's Gate 0 `motion-proof` evidence is
`earth-root-observatory-gate1-board.svg` — a still drawing. The validator only
checks that the file exists. Either the contract should require a capture
(video/animated) artifact for `motion-proof`, or the visual-bridge rule should
be softened for Gate 0 where only the hand path (not timing) is being proven.
Pick one; today the two documents disagree and the looser reading won.

### F3. Named checks with undefined semantics

`sequence-parity` and `route-duration` (Gate 2) appear in the contract with no
definition of what passing means. Earth improvised reasonable answers (GLB
metadata carrying sequence IDs + live playback; measured walk time), but an
undefined check is a self-graded check. Give each named check a one-line
pass criterion in `gate-contracts.md`.

### F4. `revisionHistory` is load-bearing but invisible to the validator

The schema silently accepts unknown keys, so the entire rejection record —
the most valuable part of Earth's manifest — is unvalidated free-form JSON.
Nothing enforces digest format, gate-id validity, or that a rejected revision
implies the gate regressed. Add an optional `revisionHistory` section to the
schema with the same digest/gate-id/timestamp rigor as everything else.

### F5. Gate 0 is self-graded prose

Gate 0 finishes as `verified` with no human, and its `canon-conflicts` check
evidence is a sentence ("Production contract records the … conflict"). A
plausible-sounding paragraph passes. This is partially inherent (canon audit is
prose by nature), but where a machine artifact exists (report JSON, digest
list) the contract should require pointing at it rather than at a claim about
it. At minimum, note in SKILL.md that Gate 1's human review implicitly audits
Gate 0's honesty.

### F6. One file can satisfy every evidence kind

Evidence kinds must be unique within a gate, but three kinds may all point at
one board SVG (Earth does: floor-plan, vertical-section, route-storyboard →
same file). Multi-panel boards are legitimate, so don't ban this — but the
validator could warn when N kinds share one digest, prompting the human to
confirm the panels actually exist.

## Cost and approval-gate assessment

- Six human gates per room across ~8 cave rooms is a real tax on Austen. The
  exemption mechanism exists but forbids "convenience" rationales, leaving no
  sanctioned way to run a lighter pass on a minor or grammar-reusing room. Now
  that `2026-08-05-vulcan-cave-ornament-grammar.md` exists, a room that reuses
  an approved visual grammar should be allowed to merge Gate 3 into Gate 2
  (registered cameras + material families in the graybox review) by recorded
  decision, not by exemption-per-artifact.
- No gate is redundant as written; Gate 3 is the only merge candidate.
- The comprehension check is the most expensive per-approval step. Keep it, but
  scope it to gates where spatial understanding changed (a Gate 1.1-style
  amendment that moves two performers deserves it; a re-approval after a
  non-spatial evidence fix does not).

## Visual bridge assessment

Strong and matches Austen's actual failure modes. Two gaps:

- It never names the **free-walk** as a bridge artifact, yet the free walk is
  what invalidated a passed gate. Add "walkable first-person route" to the
  diagnosis table's answer for "How large does it feel?" — it's already implied
  but should be the explicitly preferred artifact from Gate 2 onward.
- The comprehension check has no guidance for partial reads (user gets 6 of 7
  right). State that any wrong element keeps the gate open — currently implied
  by gate-contracts but not by the checklist itself.

## Blender / runtime / capability-ownership gaps

- The First Fire pipeline (TypeScript plan → exported JSON manifest → headless
  `--factory-startup` build → `FF_`-prefixed export → optimize → verify, with a
  round-trip coordinate test at twelve decimals) is the best-executed part of
  the whole production system, and the skill never names it. Gate 2 should
  reference it as the canonical build pattern instead of leaving each scene to
  rediscover it. Fire and Earth each have private builder scripts; a third
  scene (Water) should extract the shared skeleton per `never-hand-roll.md`.
- The skill correctly routes performer bodies to `MuseumPerformerStation3D` and
  collision to the TypeScript terrain contract — but only in the Earth
  contract's prose, not in the skill. Move the runtime ownership boundary
  (GLB = static visuals only; collision/progression/performers = code) into
  `gate-contracts.md`'s authority table. It is currently re-derived per scene.

## Validator bypass / false-reject audit

- Bypass: approval quotes are unverifiable strings; a fabricated quote passes.
  Mitigated by the required `museumTrackerItem` cross-reference — keep that
  mandatory, and have synthesis consider requiring the tracker item to be a
  `decision` with verdict `accepted`.
- Bypass: `checkFiles: false` is available programmatically; the CLI always
  checks files. Fine.
- False reject: none found. The Earth manifest — including a gate at
  `ready-for-review` with rejected revisions in history — validates, which is
  correct behavior.
- The `currentGate` derivation (first incomplete gate) is strict and correct;
  it caught nothing on Earth only because Earth's author already complied.

## One real counterargument to the gated approach

The two best outcomes this museum has produced — First Fire ("way better than
the other grayboxes") and Earth's rapid Gate 1 → free-walk → Gate 1.1 loop —
came from fast iteration on **walkable artifacts**, not from manifest
bookkeeping. The gates codify the shape of that loop after the fact; the risk
is that on the next room the agent spends its effort satisfying the evidence
index (seven evidence kinds, digest maintenance, claim ledgers) instead of
getting Austen into a walkable space quickly, and that the process ossifies the
current toolchain right before a room that needs a different one. The honest
rebuttal: the manifest cost Earth very little and made its failures legible.
But the process should state its own escape valve plainly — when the manifest
and the walkable artifact compete for effort, the walkable artifact wins, and
the manifest catches up afterward.

## Recommendations in priority order

1. F1 — redefine Gate 1 `sightlines` as moving, floor-aimed sampling windows.
2. F3 — one-line pass criteria for every named check.
3. F2 — resolve the motion-proof still-frame contradiction.
4. Name the First Fire build pipeline as the canonical Gate 2 pattern; extract
   the shared builder skeleton at the third scene.
5. F4 — schema-validate `revisionHistory`.
6. Add the grammar-reuse Gate 2+3 merge path for rooms under an approved
   ornament grammar.
7. F5/F6 — Gate 0 machine-artifact preference; shared-digest warning.
8. Move the runtime ownership boundary into the skill's authority table.

## Parts that should remain unchanged

The authority table, the claim taxonomy, the exemption provenance rules, the
approval-record structure (including `visualComprehensionConfirmed`), the
preserved-rejection policy, the gate ordering itself, and the validator's
strictness. Do not soften "praise is not approval" — Earth's invalidated
"Love it. Gate passed." is the proof it earns its place.
