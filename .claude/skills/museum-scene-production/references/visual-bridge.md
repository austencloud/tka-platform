# Visual Bridge

Use this reference when prose does not produce a stable mental picture.

## Diagnose the missing representation

| User cannot answer | Produce |
|---|---|
| Where am I and where can I walk? | Annotated top-down plan |
| What is above, below, hidden, or elevated? | Long section or cutaway |
| What happens first, next, and last? | Numbered route strip with one frame per event |
| What can I see from each stop? | Sightline cones and eye-level camera frames |
| How large does it feel? | Player-scale silhouettes, dimensions, and first-person graybox |
| What is the hero? | One hierarchy diagram plus the first and final hero views |
| How does the room react? | State storyboard or short captured interaction loop |
| How does performance become environment? | Actual live motion capture beside the proposed environmental trace |

## Artifact rules

- Use labels and arrows that survive without accompanying prose.
- Put the route in a numbered sequence. Do not make the user infer order from a
  decorative image.
- Show entry and exit in every spatial overview.
- Register concept art to approved camera views. Reject freeform images as
  spatial proof.
- Show hidden geometry with dashed lines or a separate cutaway.
- Include a human-scale figure and camera eye height.
- Use the same coordinate contract for the plan, Blender file, GLB, and runtime
  review route.
- Display `literal`, `metaphor`, and `invention` beside any motion-driven effect.
- Capture continuous motion as a loop. A still frame cannot prove timing.

## Comprehension check

Before approval, ask the user to explain:

1. where they enter;
2. what calls their attention first;
3. the order of the route;
4. what they do at each interaction;
5. what changes because of those actions;
6. where the final view occurs;
7. how they leave.

Treat a mismatch as an artifact failure, not a user failure. Revise the diagram,
section, storyboard, or blockout until the user's account matches the intended
experience.
