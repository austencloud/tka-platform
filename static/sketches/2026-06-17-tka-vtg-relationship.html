0TL;DR

TKA and VTG describe the same physical prop spinning, but from opposite design centers and with two different reference frames. The biggest source of confusion: they don't share an origin — TKA measures the prop relative to the center of the grid; VTG measures it relative to gravity (the downbeat, straight down). Nearly every "why don't these line up" traces back to that. The club (a one-ended prop both systems support) is the clean translation point.

1Origins: opposite design centers you

  • TKA was built for two-ended props (staff), then adapted to one-ended.
  • VTG was built for one-ended props (poi/club), then adapted to two-ended.
  • The club is the Rosetta stone: one-ended, exists in both, translates without ambiguity.
  • Consequence: a two-ended prop doubles the petal count of a one-ended prop doing the same motion. So petal counts mean the single-ended (club) count unless stated.

2Two reference frames (the root of all confusion)

  • TKA is center-referenced. Orientation = the prop's angle relative to the grid center. MCP
  • VTG is gravity-referenced. Its anchor is the downbeat — the south / bottom of the prop's circle. VTG reads a pattern by when the props cross the downbeat. MCP VTG
  • The frames only coincide at specific grid points (line up at south; 90° apart at east; …). So conversion is position-dependent — not a constant offset but a per-position rotation (a "conversion table"). infer

3Orientation: 8 points (TKA) vs 2 (VTG)

  • TKA — 8-point center-relative cycle: in → clockIn → clock → clockOut → out → counterOut → counter → counterIn. MCP
  • VTG has only two orientations: in and out. you VTG — the prop glyph is a circle with a line for in vs out; the props axis is Props Out / Props In / Props In-Out.
  • The prop passes through clock/counter/interradial angles, but VTG never names or references them — transit, not landmarks. Clock, counter, "nonradial" are TKA-only. you

4Spin type & base rotation

  • Inspin (VTG) = prospin / pro (TKA): prop rotates the same direction as the hand's path. MCP VTG
  • Antispin = anti: prop rotates opposite the hand's path. MCP
  • Base rotation: TKA turn counts measure additional rotation on an inherent base. At 0 turns, a curved shift's pro and anti are already two different states (pro base preserves center-relative orientation, anti reverses). "0 turns" ≠ "no spin." MCP
  • 1 TKA turn = 180° of additional rotation. MCP

5Turn ratio (props:hands) and the TKA↔VTG turn map

  • Ratio convention is props:hands (N:1) = N prop rotations per one hand revolution. Canonical across VTG1, VTG2 Index, VTG2 Ch.1–2: "every one rotation of the hand corresponds to one rotation of the prop" = 1:1. VTG1 p4
  • Our app uses props:hands everywhere; the old VTG app's 1:3 is just the inverse (hands:props) order. We're aligned with Yee. code you

6Petals: a SEPARATE count from ratio

The correction that mattered. Petal count and turn ratio are two different measurements against two different references. you

  • Petals are read off the radial reference: out for antispin, in for inspin. This is the flower shape. you
  • Turn ratio / timing is read off the downbeat (gravity) — nothing to do with the petal reference. you
  • They correlate cleanly but aren't the same act. Single-ended (club) formulas code:
    • Inspin petals = N − 1 = 2·turns (1:1 → 0 petals = plain circle).
    • Antispin petals = N + 1 = 2·turns + 2 (1:1 → 2; 3:1 → 4).
    • Your example: 4-petal antispin = 3:1 = 1 TKA turn on a club. ✓
  • Two-ended props double these counts. Formulas above are single-ended. you
The earlier research agent claimed "4-petal antispin = 4:1" — wrong; it conflated petal count with ratio. Discarded.

7The simplest antispin: trammel → oval you

  • TKA 0 turns = VTG 1:1 antispin = the "2-petal antispin," but at its smallest form it doesn't cross itself — it's a long, thin shape.
  • If the prop tip sat exactly at the grid midpoint (prop length = half the grid), it collapses to a literal straight line — a trammel (the Roman device: two points sliding on fixed straight lines).
  • We deliberately offset the tip so it renders as a wide oval instead of a line — keeping it visually distinct from a dash (which also draws a straight line). VTG made the same choice; it's the horizontal/vertical antispin.

8Modality: timing & direction (and where TKA extends VTG)

  • Direction: same vs opposite — do the two hands orbit the same way or mirrored. code
  • Timing: measured by downbeat-crossing phase between the hands (both at south = together; 180° out = split). MCP
  • VTG natively had only Together and Split timing (× same/opposite) → 4 modes: T/S, T/O, S/S, S/O, exactly what the notation pages show. VTG you
  • Quarter timing (gamma) is a TKA extension VTG never classified — Austen added it (Sun/Moon = 90° phase). TKA has 6 modes (adds Quarter-Same, Quarter-Opp) where VTG had 4. MCP

9What our code already does (the bridge)

  • The downbeat conversion is already implemented. tnd-deriver.ts extrapolates each hand's phase to south (phaseToSouth(loc, dir)) before reading timing/direction — that is the position-dependent conversion table from §2. Purely geometric. code
  • The mandala is pure geometry: per beat, staffDelta = ±centerMovement + turns·π (pro = +, anti = −). Shape = prop-spin sign + hand arc (centerMovement) + turns; start orientation sets the rosette's phase. code
  • Two-ended vs one-ended is the mandala's tipEnds (staff = both tips, club = one). code

10Implications for the labeling system

  • The orientation axis for VTG naming is in/out only (spin picks which anchors the petals: out for antispin, in for inspin). Clock/counter get no VTG names. A core's name keys off (spin, ratio, in-vs-out) — not a 4-way orientation.
  • Petals come from the ratio via the single-ended formulas (§6); display doubles for staff.
  • Timing / modality is the separate downbeat read — it belongs to the two-hand combination, not the single-hand core.
  • So a per-hand core = spin × ratio (props:hands) × radial-reference (in/out) → a VTG name + petal count. The two-hand cell adds timing/direction on top.
